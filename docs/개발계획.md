# 개발계획: Fear Our Creation (Unity 2D)

기획.md의 '제작 순서'를 기준으로, 유니티 구현 관점의 아키텍처·마일스톤·검증 기준을 정리한 문서.
수치는 전부 기획서의 '반복적 조절이 필요한 요소' 표를 따르며, 코드에 하드코딩하지 않고 ScriptableObject로 분리한다.
만일 에셋이 필요한 요소(그래픽, 사운드 등)가 있다면 플레이스홀더로 대체 후 추후 정식 에셋으로 대체할 자리를 명시한다.

## 1. 기술 스택과 프로젝트 설정

| 항목            | 결정                                                | 이유                                                                                         |
| --------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 엔진            | Unity 6 (LTS)                                       | 2D 기능 안정, 최신 URP 2D                                                                    |
| 렌더 파이프라인 | URP 2D Renderer                                     | 흰 배경 + 색 규칙 중심이라 라이팅은 최소. 후반 연출(소각 불길, 촉수 잠식)에 Volume 활용 여지 |
| 입력            | Input System 패키지                                 | WASD / 마우스 / Space / R을 Action Map으로 관리, 이후 리바인딩 가능                          |
| 물리            | Physics2D                                           | 벽 충돌, 투사체, 폭발 범위 판정                                                              |
| 카메라          | Cinemachine 2D (탑뷰 고정 추적)                     | 화면 가로 길이 기준 수치(어그로 반경, 시야)가 많아 카메라 크기를 고정값으로 유지             |
| 해상도          | 16:9 고정, Orthographic Size 고정                   | '화면 가로 길이'를 월드 단위 상수로 환산하기 위함                                            |
| 타일맵          | Tilemap + Composite Collider 2D                     | 벽/바닥 제작, 레벨 디자인 속도                                                               |
| 텍스트/UI       | uGUI + TextMeshPro (한글 폰트 에셋)                 | 통화 자막, 안내방송 자막                                                                     |
| 오디오          | AudioMixer (BGM / SFX / Voice / Announcement)       | 앰비언트 + 무음 구간 중심                                                                    |
| 버전관리        | Git + Unity용 .gitignore, Git LFS(오디오/큰 텍스처) |                                                                                              |

### 단위 기준 (모든 수치의 기준점)

- `PlayerDiameter` = 1.0 유닛으로 고정. 사거리/폭발 지름은 전부 이 배수로 데이터에 기록
- `ScreenWidth` = 카메라 Orthographic Size로부터 계산한 월드 폭. 어그로 반경(1배), 적 시야(0.5배)에 사용
- 이 두 값은 `GameConstants` 하나에서만 정의

## 3. 핵심 아키텍처

### 3.1 데이터 주도 설계 (ScriptableObject)

- `WeaponData`: 종류(Melee/Ranged/Thrown), 사거리, 부채꼴 각도, 발동 딜레이, 공격 간격, 탄창/묶음 크기, 소지 상한, 회수 확률(명중/빗나감), 보스 피해량 가중치
- `EnemyData`: 이동속도 배수, 시야 각도/거리, 공격 딜레이/간격, 사용 무기, 체력 방식(즉사/카운트다운), 노획 무기
- `ExplosiveData`: 폭발 지름, 이펙트 종류(폭발/독성 물결), 연쇄 여부
- `BossData`: 체력(근접 4회분), 호출 상한/쿨다운/모션, 사격 예고 시간, 손상 단계 임계값
- `StageData`: 씬 이름, 시작 연출 재생 여부 규칙, 초기 지급/제거 무기(6스테이지 무기 제거)

보스 피해량은 "근접 1회 = 가시 6 = 권총 8발 = 폭탄알 1발"이므로, 보스 체력을 100으로 두고 무기별 `bossDamage`를 근접 25 / 가시 25÷6 / 권총 25÷8 / 폭탄알 25로 계산해 넣는다(수식은 에디터에서 자동 계산).

### 3.2 피해와 즉사 모델

- `IDamageable.TakeHit(HitInfo)` 하나로 통일. `HitInfo`에 출처(Player/Enemy/Environment), 종류(Melee/Projectile/Explosion), 폭탄알 여부 포함
- 플레이어/일반 적: 1회 피격 즉사
- 뚱보 창병: 카운트다운 컴포넌트(`DelayedDeath`). 첫 피격 2초, 추가 피격마다 0.2초 단축, 폭탄알·오브젝트 피해는 즉사. 피 흘림 표시로 시작을 알림
- 보스: 누적 피해량 방식, 25% 단위 4단계로 방호복 스프라이트 교체
- 아군 오사 없음은 `HitInfo.Source`로 필터링(적 폭탄알은 적을 무시, 플레이어 폭탄알은 플레이어 무시). 단, 환경 오브젝트 파손은 출처와 무관하게 동작

### 3.3 맵 진입 스냅샷과 R키 재시작 (최우선 시스템)

기획의 핵심 요구. 소프트락 방지가 목적이므로 초기에 견고하게 만든다.

- 씬을 다시 로드하지 않고 **저장된 상태로 재구성**하는 방식 대신, 1차 구현은 **씬 리로드 + 진입 시 상태 주입**으로 단순화
  - 스냅샷 = `PlayerLoadout`(소지 무기, 잔량) 만 직렬화. 맵 내 배치(적, 무기, 시신)는 씬 자체가 진입 시점 상태이므로 리로드로 자연 복원됨
  - 이월 무기는 `GameManager`(DontDestroyOnLoad) 또는 정적 컨테이너가 보관
- 맵 진입 시점에 `SnapshotSystem.Capture()` 호출, R키 → `Restore()` 후 씬 리로드
- 6스테이지 진입 시 무기 제거 **후에** 스냅샷을 저장(기획 명시)
- 무전투 연출 스킵 규칙은 `StageData.skipCutsceneOnRestart` 플래그와 "이번이 재시작인가" 상태로 판단
  - 2스테이지 시작 통화, 3스테이지 종료 통화, 5스테이지 보스전 진입 연출, 6스테이지 진입 연출
- 재시작 지연은 최소화(사망 후 0.3초 내에 R 입력 수용, 페이드 없이 즉시 로드)

### 3.4 적 AI 상태머신

- 상태: `Idle/Patrol → Alert → Chase/Attack`, 경계 해제 시 복귀
- `Perception` 컴포넌트가 시야(부채꼴, 벽 차단 레이캐스트)와 청각(이벤트 구독)을 분리 담당
  - 시야: 전방 90도, 화면 가로 절반. 플레이어까지 `Raycast`로 벽 레이어 체크
  - 청각: 권총 발사 시 `SoundEventBus.Publish(new SoundEvent(위치, 반경, 지속))` 브로드캐스트(구독은 `SoundEventBus.Emitted`). 벽 차단 없음, 반경 내 적이 발사 지점으로 이동, 지속 5초
- 공격은 예고 모션 없이 발동 딜레이 후 판정(창병 0.2초). 판정 시점에 범위 재계산
- 종류별 공격 클래스: `MeleeAttack`(부채꼴), `ProjectileAttack`(가시), `GrenadeAttack`(폭탄알)
- 길찾기: 벽이 정적 지형이므로 Tilemap 기반 그리드 A* 자체 구현 또는 A* Pathfinding Project 사용 검토(3단계 초입에 결정). NavMesh는 쓰지 않음

### 3.5 벽과 물리 레이어

레이어: `Wall`, `Player`, `Enemy`, `Projectile`, `Destructible`, `Pickup`, `SightBlocker`

- `Wall`: 이동/시야/투사체 모두 차단, 폭발도 차단(폭발 판정 시 중심에서 대상까지 Wall 레이캐스트)
- 화분, 제어 패널은 프리팹만 다르고 동일 `Wall` 레이어(규칙 일원화)
- `Destructible`(탄약 상자, 세척수 탱크)은 Wall이 아님. 시야는 차단하지 않고 투사체는 흡수하며 파손됨
- 폭탄알은 벽 또는 적 접촉 시 폭발, 벽 접촉도 폭발 트리거

### 3.6 폭발/파괴 오브젝트 (공용 프리팹)

- `ExplosiveProp` 하나에 `ExplosiveData`만 교체해 탄약 상자(지름 4배)와 세척수 탱크(지름 6배) 구현
- 파손 시 `OverlapCircle` → 각 대상에서 Wall 레이캐스트로 차단 확인 → 즉사 처리
- 연쇄: 폭발 범위에 다른 `ExplosiveProp`이 있으면 다음 프레임(또는 짧은 지연)에 파손. 무한 재귀 방지를 위해 큐 방식으로 처리
- 플레이어 포함 즉사. 폭탄알 플레이어 면역은 폭탄알 폭발에만 적용되고 오브젝트 폭발에는 적용 안 됨(기획 준수)

### 3.7 무기 시스템

- `WeaponHolder`: 현재 무기 1개 + 잔량. 없으면 `Fist`
- 스페이스: 발밑 `Pickup` 탐색 → 현재 무기를 그 자리에 드롭(잔량 유지) → 새 무기 장착
- 합산 습득: 같은 종류 원거리 무기(투척 가시, 폭탄알) 습득 시 잔량 가산, 상한(12 / 2) 클램프. 상한 초과분은 바닥에 남김
- 소진 시 자동으로 주먹 복귀, 소진 무기는 제거. 권총 빈 총도 제거
- 투척 가시 회수: 명중 50%, 빗나감 100%. 가시를 들고 있을 때만 자동 획득(스페이스 교체와 별개 경로)
- 원거리 사거리는 맵 끝까지 = 벽/적 접촉 전까지 소멸 없음(화면 밖 오브젝트 풀 정리용 안전 수명만 둠)

## 4. 마일스톤

각 마일스톤은 **플레이 가능한 상태**로 끝낸다. 기획서 제작 순서와 1:1 대응.

### M0. 프로젝트 셋업 (0.5주)

- Unity 프로젝트 생성, 패키지(Input System, Cinemachine, TMP, 2D Tilemap), 폴더 구조, Git
- `GameConstants`(PlayerDiameter, ScreenWidth), 레이어/충돌 매트릭스, 카메라 고정
- 플레이스홀더 아트 규칙: 흰 배경, 청록 오브젝트, 붉은 적, 노란 위험 표식. 도형 스프라이트로 시작
- **완료 기준**: 빈 씬에서 플레이어(원)가 카메라 안에 표시됨

### M1. 이동·공격·즉사·재시작 (1주) — 제작순서 1

- WASD 이동, 마우스 방향 조준 회전, 좌클릭 주먹 공격(발동 딜레이 0.1초, 간격 0.5초, 좁은 직선 범위)
- 더미 적(정지) 1회 피격 즉사, 플레이어 즉사
- R키 재시작 + `SnapshotSystem` 골격
- **완료 기준**: 더미 적을 주먹으로 잡고, 죽으면 R로 즉시 재시작. 재시작 지연 0.5초 이내

### M2. 무기 시스템 + 데이터 분리 (1.5주) — 제작순서 2

- `WeaponData` SO 전체 정의(주먹, 가시창, 투척 가시, 폭탄알, 권총)
- 스페이스 교체/드롭(잔량 유지), 주먹 기본값, 소진 시 복귀, 합산 습득, 소지 상한
- 투척 가시 회수 규칙, 폭탄알 폭발(적/벽 접촉, 지름 4배)
- 스테이지 간 무기 이월 구조(`PlayerLoadout`)
- 권총: 16발 탄창, 초당 8발, `SoundEventBus`로 발사 소리 이벤트 발행(수신자는 M3)
- **완료 기준**: 테스트 씬에서 모든 무기를 습득·교체·소진해 보고, 수치를 SO에서만 바꿔 동작이 바뀜. 재시작 시 스냅샷의 탄약·무기 복원 확인

### M3. 적 AI 4종 + 벽 + 1~2스테이지 (2.5주) — 제작순서 3

- 벽/화분/제어 패널 프리팹, 시야·투사체·폭발 차단
- `Perception`(시야 부채꼴, 소리 감지), 상태머신, 길찾기
- 가시 창병, 가시 투척병, 척탄병(폭탄알 투척 5초 간격), 뚱보(M4에서 완성) 중 우선 3종 구현
- 노획 드롭(적 사망 시 해당 무기 Pickup 생성): 가시창, 투척 가시 6개 묶음, 폭탄알
- **1스테이지 제작**: 오프닝 벽 붕괴 + 촉수 연출(간단한 스프라이트 애니메이션), 튜토리얼 순서(뒤에서 주먹 처치 → 가시창 노획), 화분 활용
- **2스테이지 제작**: 통화 연출(재시작 시 생략), 투척병 대응(벽 규칙 학습), 엘리베이터 종점
- **재미 검증 게이트 (중요)**: 1~2스테이지를 실제로 플레이해서 "빠른 즉사 액션 + 빠른 재시작"의 재미를 확인. 여기서 통과하지 못하면 이후 스테이지 작업 전에 수치·AI를 재조정하고, 필요하면 범위를 축소한다
- **완료 기준**: 1~2스테이지 첫 클리어까지 10분 이내, 사망 원인이 대체로 "예측 가능"하다는 플레이테스트 피드백

### M4. 뚱보 + 폭발 오브젝트 + 3스테이지 (1.5주) — 제작순서 4

- 뚱보 카운트다운(2초, 0.2초 단축, 폭탄알/오브젝트 즉사), 피 표시로 시작 알림
- `ExplosiveProp` 공용 프리팹(탄약 상자/세척수 탱크), 연쇄, 폭발 벽 차단
- **3스테이지**: 계단(한 층), 무기고 전투(권총 획득, 발사 어그로 체험), 무기고 통화 = 맵 종료 연출(재시작 시 생략), 탄약 상자 배치
- 복선 소품: 벽 게시물/안내문에 '비상 소각 시스템', '지하터널 인증 절차' (2~3스테이지에 배치 — 2스테이지 소품은 M3 이후 소급 추가)
- **완료 기준**: 폭발 연쇄가 예측대로 동작하고, 플레이어가 자기 폭발에 죽는 경우가 시각 경고(노란 표식)로 납득 가능

### M5. 4스테이지 (2주) — 제작순서 5-1

- **4-1 사무실**: 무전투. 모든 모니터에 동시 메시지, 촉수가 키보드를 치는 연출, 지하터널 인증 실패 로그 모니터
- **4-2 배양실**: 배양 탱크 기습(대규모 스폰), 척탄병 첫 등장, 세척수 탱크(지름 6배), 경비병 시신 4곳(진입 직후, 세척수 탱크 구역, 중앙 통로, 엘리베이터 앞)에 권총 탄창 배치
- 재시작 지점은 4-2 시작(4-1 연출 스킵)
- 성능 점검: 대규모 적 + 권총 연사 시 프레임 유지(투사체 오브젝트 풀 필수)
- **완료 기준**: 권총 연사로 무리를 돌파하는 카타르시스와 세척수 탱크 활용이 동시에 성립. 시신 배치 없이도 불가능하지 않되, 배치 시 권장 경로가 되는지 확인

### M6. 5스테이지 보스전 (2주) — 제작순서 5-2

- 진입 연출: 소장 등장 → 직원 살해 → 방호복 얼굴 판 너머 촉수 공개(재시작 시 스킵), 키카드 더미 소품
- 보스 패턴: 후방에서 가시 원거리 사격(0.8초 예고선) + 잡몹 호출(동시 4기, 쿨다운 12초, 호출 모션 1.5초 동안 사격 중단)
- 호출 구성: 가시 창병 위주, 척탄병 최대 1기, 캣워크 경로로 합류
- 배치: 플레이어 - 제어 패널(벽) - 잡몹 - 보스. 폭탄알은 잡몹 공급으로 노획
- 방호복 손상 4단계(25% 단위) 스프라이트 교체
- 피해량 검산 테스트: 근접 4번 / 가시 24발 / 권총 32발 / 폭탄알 4발
- **완료 기준**: 평균 도전 횟수 5~10회 내 클리어, "노획 → 사용" 루프가 자연스러움. 폭탄알 상한 2발 검증

### M7. 6스테이지 + 엔딩 (1주) — 제작순서 5-3

- 진입 시 무기 제거(주먹만) + 그 상태로 스냅샷 저장
- 깔때기형 맵, 무한 스폰 가시 창병 떼(노획 불가), 오른쪽으로 몰리는 압박 구조, 자폭 버튼
- 엔딩 연출: 불길, 소각 구역 탈출 불가를 시사하는 컷
- **완료 기준**: 처음 플레이해도 "싸워서 이길 수 없다 → 버튼으로 간다"가 자연스럽게 읽힘

### M8. 폴리시·연출·사운드 (2주)

- 앰비언트 사운드, 무음 구간, 연구소 안내방송(Voice 믹서 채널)
- '상황은 통제하에 있음' 반복 문구 변주(2스테이지 통화, 4-1 송신문)
- 적 실루엣/크기 가독성 최종 점검(흰 배경 대비), 폭발물 노란 표식 일관성 점검
- 화면 흔들림, 피격 이펙트, 통화/터미널 UI
- 옵션(볼륨), 일시정지, 타이틀 화면

### M9. 밸런싱·QA·빌드 (1.5주)

- 반복 조절 표의 수치 일괄 재조정, 플레이테스트 3회 이상
- 재시작 소프트락 전수 점검(스테이지별 탄약 소진 상태에서 R)
- Windows 빌드(IL2CPP 또는 Mono), 저사양 PC 프레임 확인

### 여유 시 추가(기획서의 선택 항목)

- UI 촉수 잠식 연출, 안내방송 점진적 왜곡, 세척수 잔류 장판

**총 예상 기간: 약 15~16주(1인 개발 기준, 아트는 플레이스홀더 후 교체 포함).** 아트/사운드를 별도 인력이 맡으면 병렬화가 가능하다.

## 6. 기획서에서 확인이 필요한 항목

구현 중 막히지 않도록 미리 결정해야 하는 빈칸. 임시값을 제안하며, 프로토타입에서 조정한다.

1. **투척병 가시 속도**: 표에 '임의값'으로만 있음. 임시로 플레이어 속도의 2.5배부터 시작
2. **보스 사격 간격**: 예고 0.8초는 있으나 연속 발사 간격이 없음. 임시로 예고 → 1발 → 1.5초 쿨다운
3. **플레이어 이동속도**: 다른 모든 이동속도의 기준값인데 절대값이 없음. 임시로 5 유닛/초
4. **권총 어그로 지속 5초**: 경계 상태 유지 시간인지, 발사 지점 추적 시간인지 구현 시 하나로 통일
5. **투척 가시 발사 간격 0.4초 vs 적 투척병 0.5초**: 의도된 차이로 보고 그대로 진행
6. **뚱보 카운트다운 중 이동**: 카운트다운 중에도 추격/공격을 계속하는지(기획상 '카운트다운 동안 계속 공격 가능'은 플레이어 기준). 적도 계속 공격하는 것으로 가정
7. **6스테이지 자폭 버튼 조작**: 스페이스 상호작용으로 가정
8. **저장/이어하기**: 기획에 없으므로 '스테이지 선택 해금' 정도로만 최소 구현(추후 결정)

## 7. 테스트 전략

- **수동 플레이테스트 중심**: 스테이지마다 "첫 클리어 시간, 사망 횟수/원인, 막힌 지점"을 기록
- **에디터 도구**: 레벨 검증(스폰 지점 벽 내부 여부, 탄약 이월 시뮬레이션), 스냅샷 확인 창, 무기 수치 미리보기
- **자동 테스트(Unity Test Framework)**: 순수 로직 위주 — 합산 습득/상한 클램프, 뚱보 카운트다운 계산, 보스 피해량 검산, 스냅샷 직렬화
- **회귀 체크리스트**: 각 마일스톤 종료 시 R키 재시작, 무기 이월, 벽 차단 규칙(시야/투사체/폭발) 확인
